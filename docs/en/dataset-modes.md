# Datasets

## Dataset modes

### `subfolders`

The simplest layout: one subdirectory per class.

```
data_dir/
  crow/
    recording1.wav
    recording2.flac
  robin/
    song_a.wav
  background/
    noise1.wav
```

If the top level contains `train/` and `test/` subdirectories, the predefined split is used (see [Manual train/test split](#manual-traintest-split)):

```
data_dir/
  train/
    crow/
      recording1.wav
    robin/
      song_a.wav
  test/
    crow/
      recording2.wav
```

### `file_per_label`

Each audio file has a paired annotation file with the same stem:

```
data_dir/
  soundscape_01.wav
  soundscape_01.txt
  soundscape_02.wav
  soundscape_02.txt
```

The `.txt` file contains tab- or comma-separated rows with `start_time`, `end_time` and `label` (no header is required):

```
0.0    3.0    crow
5.5    8.5    robin
12.0   15.0   crow
```

Audio files without a matching annotation file are skipped without a warning.

### `table`

A single CSV or TSV file maps audio segments to labels:

```yaml
dataset:
  label_mode: table
  table_file: /path/to/annotations.csv
  filename_col: filename       # default
  label_col: label             # default
  start_col: start_time        # default
  end_col: end_time            # default
  split_col: split             # optional; values: train or test (see Manual train/test split)
```

Example CSV:

```csv
filename,label,start_time,end_time,split
soundscapes/rec01.wav,crow,0.0,3.0,train
soundscapes/rec01.wav,robin,5.5,8.5,train
soundscapes/rec02.wav,crow,1.0,4.0,test
```

### Manual train/test split

When the dataset has already been split manually, the split can be declared in the configuration
instead of being generated by bioaccx. Two of the three modes support this:

**`subfolders`:** place `train/` and `test/` at the top level, each containing the class folders
(see the layout [above](#subfolders)):

```yaml
dataset:
  data_dir: /data/my_dataset   # contains train/<class>/ and test/<class>/
  label_mode: subfolders
```

**`table`** (and `ext_table_file`): add a `split` column with the values `train` or `test`:

```yaml
dataset:
  label_mode: table
  table_file: /data/annotations.csv
  split_col: split             # default column name
```

`file_per_label` has no split mechanism, since its `.txt` rows contain only `start_time`,
`end_time` and `label`. The `table` mode should be used when a manual split with timed segments
is required.

**How the split is resolved:**

| Samples with a `train`/`test` assignment | Result |
|---|---|
| All | Used exactly as given; `test_ratio` and `random_seed` have no effect on the split |
| None | Stratified automatic split using `test_ratio` and `random_seed` |
| Some | Assigned samples keep their split; only the unassigned ones are split automatically, and both are then merged |

The mixed case makes it possible to extend a manually curated dataset: an
[appended dataset](#appending-to-an-existing-dataset) or a pre-split source can be combined with an
unsplit one in the same run, and only the new material is shuffled.

The console prints `Using predefined split: train=…, test=…` when a split is taken from the
dataset, and the per-label counts in `[stem]_dataset_metadata.json` reflect it.

> **Note:** in the `subfolders` mode, a predefined split is detected when *either* `train/` or
> `test/` exists. A directory containing only `train/` therefore produces an empty test set rather
> than an automatic split, so both folders should be created.

### Exporting without a split

In the opposite case, the chunked samples are grouped **only by label**, without any train/test
split, for example to review them, to use them in another tool or to split them manually. Add
`--no-split` to `bioaccx dataset`:

```bash
bioaccx dataset my_config.yaml --no-split
```

The option is accepted only by `bioaccx dataset`, since training requires a test set, and it
overrides all other split settings: `test_ratio` is ignored, as is any split already defined by
the source (`train/` and `test/` folders, or a `split` column).

```
output_path/[stem]/
  dataset/
    crow/
      rec1_0.000_3.000.wav
    robin/
      song_a_0.000_3.000.wav
  [stem]_dataset_list.csv         # split column present but empty
  [stem]_dataset_metadata.json    # "split": "none", one count per label
```

Everything else behaves as in a normal `bioaccx dataset` run: windowing, overlap, filter and speed
preprocessing and augmentation still apply (augmentation covers every sample, since there is no
test set to keep clean).

**Defining a manual split from the export.** The resulting `[stem]_dataset_list.csv` already has
the columns expected by the `table` mode, with the `split` column left empty. After `train` or
`test` has been entered where required, the same file can be used as input:

```yaml
dataset:
  label_mode: table
  table_file: /path/to/[stem]_dataset_list.csv
  filename_col: filepath        # the path column of the CSV
  split_col: split
```

Rows left empty are split automatically, stratified by `test_ratio`, so a partially filled column
is also valid: the relevant samples can be assigned explicitly and the rest left to bioaccx.

**Reproducing a run from its embedding store.** The folder of a trained model contains everything
needed to train it again without audio: `[stem]_dataset_list.csv` (every window, with its label
and split) and the embedding store (`embeddings_cache_path` or `export_embeddings`). When used as a
table, the list rebuilds each window exactly as it was embedded, including noisy copies
(`noise_file`, `snr_db`, `noise_start_time`), shifted short signals (`signal_offset_samples`,
`signal_duration_seconds`) and multi-label windows (`labels`), so every embedding is read from the
store and no audio file is opened:

```yaml
dataset:
  label_mode: table
  data_dir: .
  table_file: my_model/[stem]_dataset_list.csv
  filename_col: filepath
  overlap: 0.0                  # each row is already one window
  random_sample_shift: false    # the offsets come from the list
  embeddings_cache_path: my_model/embeddings.db
  # no augmentation: the noisy copies are rows of the list
training:
  # the training settings of the original run
```

Audio-mixup rows are skipped, and the original `training.audio_mixup` settings draw them again. A
window missing from the store is computed from the audio, which must then be available at the
listed paths. Lists written before `noise_start_time` and `signal_duration_seconds` were recorded,
which name the noise file without its folder, still rebuild the keys of runs whose noise windows
start at 0 s; only recomputation from audio requires the newer columns.

## Appending to an existing dataset

`append_dataset_path` extends an existing dataset incrementally, without reprocessing the samples it already contains.

```yaml
dataset:
  data_dir: /path/to/new_recordings
  label_mode: file_per_label
  append_dataset_path: /path/to/existing_exported_dataset
```

**How it works:**

1. All `data_dir` paths are scanned and chunked into `AudioSample` objects as usual.
2. The existing dataset at `append_dataset_path` is loaded. It must use the `subfolders` layout with `train/` and `test/` subdirectories, which is the format produced by `export_dataset: true` or `bioaccx dataset`.
3. Each new sample is compared with the existing dataset using the filename it would have when exported (`{stem}_{start:.3f}_{end:.3f}`). Duplicates are discarded.
4. The merged set (existing samples and new unique samples) is used for the rest of the pipeline.

**Multi-label windows in an export:** a window annotated with several classes is written to each of its label folders under a single name ending in `_ml<hash>` (a hash of its source file and time bounds). Reading the export back, as `append_dataset_path` or as a `subfolders` `data_dir`, merges the copies into one multi-label window again. Files that only share a name across label folders have no such suffix and remain separate. Audio mixes are written to `dataset/mixes/`, which is never read back.

**Split assignment:** existing samples keep their original `train`/`test` assignments. New samples are split automatically, stratified by `test_ratio` and `random_seed`.

**Typical workflow:**

```bash
# First run: train on the initial data and export the dataset
bioaccx train config_v1.yaml   # with export_dataset: true

# Later: add new recordings and retrain on the full merged set
bioaccx train config_v2.yaml   # with append_dataset_path pointing to the first export
```

## Combining multiple sources in one run

A single `dataset` block describes one source with one set of options. When the training data is heterogeneous (for example, one directory in the `subfolders` layout, another in the `file_per_label` layout, and a third that requires noise augmentation while the others do not), a list of **source blocks** can be declared under `dataset.sources`, instead of chaining several `bioaccx dataset` runs with `append_dataset_path`.

Each source is loaded, split and augmented independently, and all sources are then concatenated into the final training and test sets. Splitting per source preserves the class proportions of each source in both subsets, and augmentation (or any other per-source preprocessing) applies only to the sources that request it.

```yaml
dataset:
  # Run-level settings: defined once and shared by every source
  test_ratio: 0.2
  random_seed: 42
  embedding_workers: 8

  sources:
    - data_dir: /data/curated          # class subfolders, no augmentation
      label_mode: subfolders

    - data_dir: /data/soundscapes      # Audacity-style annotations
      label_mode: file_per_label

    - data_dir: /data/rare_species     # augment ONLY this source
      label_mode: subfolders
      augmentation:
        augmentation_dir: /data/noise
        snr_levels: [20, 10, 3]

    - data_dir: /remote/recordings     # a remote source over SSH
      label_mode: subfolders
      ssh_host: host.example
      ssh_user: me
```

### Inheritance and overrides

Each source **inherits** the top-level `dataset` fields and overrides them with its own. Common options (for example, an `overlap` or a `filter`) can therefore be set once at the top level and applied to every source, while `data_dir`, `label_mode`, augmentation and other settings vary per source.

To **exclude a source** from an inherited augmentation, set `augmentation: null` on that source:

```yaml
dataset:
  augmentation:                  # applied to every source by default…
    augmentation_dir: /data/noise
    snr_levels: [10, 20]
  sources:
    - data_dir: /data/a
    - data_dir: /data/b
      augmentation: null         # …but not this one
```

### Run-level vs. per-source fields

A few fields describe the **whole run** and are read only from the top-level `dataset` block. Setting them inside a source has no effect, so that the split, the seed, the append target and the credentials are unambiguous across the run:

| Run-level (top-level only) | Per-source (overridable) |
|---|---|
| `test_ratio`, `random_seed` | `data_dir`, `label_mode`, `table_file` / `ext_table_file` |
| `append_dataset_path` | `overlap`, `min_anchor_fraction` |
| `embedding_workers`, `embeddings_cache_path` | `filter`, `filter_freq`, `filter_order`, `speed` |
| `ext_cache_dir`, `audio_extensions` | `augmentation`, `random_sample_shift` |
| `xc_api_key`, `arbimon_credentials_path` | `ssh_host` / `ssh_user` / `ssh_port` / `ssh_key_path`, label/column names |

Because **SSH settings are defined per source**, local and remote sources, including sources on different SSH hosts, can be combined freely in one run.

`append_dataset_path` remains a run-level field: the existing exported dataset is loaded once and merged (keeping its predefined `train`/`test` split), while each source still removes duplicates of its new samples against it. This works in the same way in the full pipeline, `bioaccx dataset` and `bioaccx embeddings`.

> Configurations without a `sources:` key behave exactly as before; this feature is purely additive.
